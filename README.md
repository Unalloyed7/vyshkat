# ВышКат

Консольная программа для учёта самокатов, велосипедов и вещей на балансе. Написана на C# под .NET 10.

## Как запустить

Нужен .NET SDK 10. Все команды выполняются из папки проекта.

```bash
dotnet restore src/VyshKat.Console/VyshKat.Console.csproj
dotnet run --project src/VyshKat.Console
```

При первом запуске скачиваются пакеты из NuGet. Дальше в меню можно добавить транспорт или вещь, посмотреть количество объектов, расход энергии, список для новичков и весь инвентарь.

Для готового примера:

```bash
dotnet run --project src/VyshKat.Console -- --demo
```

В нём есть успешная приёмка, отказ по техосмотру, повтор номера, добавление вещей и все отчёты. В конце получается 3 транспортных средства, 2 вещи и 8 кВт·ч в сутки. Пример вывода лежит в [docs/demo.txt](docs/demo.txt). Демонстрация не меняет данные, введённые через меню.

Данные хранятся в памяти и пропадают после выхода. Простота для новичка задаётся числом от 1 до 10. При значении от 6 транспорт попадает в список для новичков. Расход энергии не может быть отрицательным; можно вводить и `2.5`, и `2,5`.

## Как устроена программа

В [VyshKat.Core](src/VyshKat.Core) лежат модель и сервисы, в [VyshKat.Console](src/VyshKat.Console) - меню и настройка DI, в [VyshKat.Tests](tests/VyshKat.Tests) - тесты.

У [InventoryItem](src/VyshKat.Core/Model/InventoryItem.cs) есть название и инвентарный номер. От него идут две ветки: `Transport` для транспорта и `Equipment` для вещей. Транспорт представлен классами `Bicycle`, `Scooter` и `ElectricBicycle`, вещи - `Helmet` и `ChargingStation`.

Для инвентаризации есть интерфейс [IInventoryItem](src/VyshKat.Core/Model/IInventoryItem.cs), для расхода энергии - [IEnergyConsumer](src/VyshKat.Core/Model/IEnergyConsumer.cs). Второй реализуют электротранспорт и зарядная станция. Велосипеду и шлему он не нужен. Расход двух электрических видов транспорта хранится в общей базе `ElectricTransport`.

Парк хранится в [FleetService](src/VyshKat.Core/Services/FleetService.cs). Перед добавлением транспорта проверяется номер, затем вызывается техосмотр. Если он отказал, объект не добавляется и его номер остаётся свободным. Номера транспорта и вещей не могут повторяться; регистр и пробелы по краям не учитываются.

[ServiceCenter](src/VyshKat.Core/Services/ServiceCenter.cs) проверяет признак `IsTechnicallySound`, который задаётся при вводе. Для этой задачи осмотр упрощён до ответа «исправен / неисправен». Вещи добавляются без транспортного осмотра. Энергия считается по всему балансу, включая зарядные станции.

## SOLID

**SRP.** У классов разные задачи: модель хранит и проверяет характеристики, `ServiceCenter` проводит осмотр, `FleetService` ведёт парк, `ConsoleApplication` работает с пользователем.

**OCP.** Новый вид транспорта можно добавить наследником `Transport` или `ElectricTransport`. Приёмку и отчёты менять не придётся.

**LSP.** Все виды транспорта можно передать в один метод приёмки. У них общие ограничения на характеристики. Шлем не наследуется от транспорта и не получает ненужных транспортных свойств.

**ISP.** Инвентарный номер и расход энергии вынесены в разные интерфейсы, поэтому не каждый объект обязан потреблять энергию.

**DIP.** `FleetService` получает [IServiceCenter](src/VyshKat.Core/Services/IServiceCenter.cs) через конструктор. Конкретный сервис подключается в [CompositionRoot](src/VyshKat.Console/CompositionRoot.cs) через Microsoft.Extensions.DependencyInjection. Это самый явный пример SOLID в программе: в тестах осмотр легко заменить заглушкой.

OCP здесь соблюдён не везде: при добавлении нового вида транспорта надо дописать пункт меню и его создание в `ConsoleApplication.AddTransport`. Для трёх видов обычный `switch` проще отдельной системы фабрик. Короткие отчёты тоже оставлены в `FleetService`, без отдельного класса на каждый подсчёт.

Если добавить сотрудника, понадобится отдельная модель: по условию сотрудник не ставится на баланс. Склад с учётом количества деталей тоже будет отдельным сервисом. Штучную запчасть с собственным номером можно сделать наследником `Equipment`. Уже написанные приёмка и отчёты транспорта от этого не изменятся.

## Тесты

```bash
dotnet test tests/VyshKat.Tests/VyshKat.Tests.csproj --collect:"XPlat Code Coverage" --settings coverage.runsettings --results-directory TestResults
```

`FleetServiceTests.InspectionDecisionIsReplacedThroughContainer` подменяет `IServiceCenter` в DI-контейнере. Ответ заглушки специально противоположен состоянию транспорта: проверяется, что парк следует решению осмотра.

`ModelTests.BeginnerRuleUsesSixAsInclusiveBoundary` проверяет простоту 1, 5, 6 и 10. `ReportIncludesEnergyOfTransportAndEquipment` проверяет сумму энергии, список для новичков и то, что отклонённая техника не учитывается.


## Использование ИИ

ИИ помог с модулем учёта парка `FleetService`: приёмкой транспорта после техосмотра, подсчётом энергопотребления и выбором транспорта для новичков.
